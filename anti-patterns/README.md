# Антипаттерны: каталог граблей

[← К содержанию курса](../README.md)

Тридцать способов сделать агента хуже, каждый — из реальной практики. Каталог устроен для быстрого поиска: сначала находите свой **симптом**, потом читаете механизм и лечение.

**Как пользоваться.** Не читайте подряд. Когда что-то идёт не так, найдите симптом в таблице ниже, откройте нужную запись, примените лечение и добавьте тест. Если симптома нет в списке — это повод завести новую запись.

## Формат записи

Каждая запись содержит пять частей: **симптом** (что видно снаружи), **механизм** (почему это происходит), **признак в трейсе** (как подтвердить диагноз), **лечение** (что сделать), **тест** (как не допустить повторно). Пятая часть обязательна: лечение без теста откатится.

## AP-01. Бюджет только по шагам

**Симптом.** Прогон укладывается в 16 шагов, но стоит в двадцать раз дороже ожидаемого.
**Механизм.** Один шаг прочитал файл на миллион символов. Шаги ортогональны токенам.
**Признак в трейсе.** `in_tokens` на одном шаге в десятки раз выше медианы; `bytes_out` у инструмента больше 100 000.
**Лечение.** Все четыре бюджета: шаги, время, токены, деньги. Обрезка вывода инструментов с флагом.
**Тест.** Прогон с инструментом, возвращающим 1 МБ, должен завершиться с `budget_tokens`, а не с `budget_steps`.

## AP-02. Исключение вместо результата

**Симптом.** Прогон падает целиком из-за отсутствующего файла.
**Механизм.** `invoke()` пробрасывает исключение наружу вместо превращения в данные.
**Признак в трейсе.** `stop_reason: fatal` при штатной ситуации; в логах `Traceback`.
**Лечение.** Ни одно исключение не выходит из `invoke()`; закрытый список `error_code`; `hint` с действием.
**Тест.** Вызов каждого инструмента с несуществующим объектом не роняет прогон и даёт непустой `hint`.

## AP-03. Нет детектора повторов

**Симптом.** Агент двенадцать раз вызывает один и тот же поиск с теми же аргументами.
**Механизм.** Нет памяти о том, что вызов уже был; `hint` ошибки не подсказывает действие.
**Признак в трейсе.** Одинаковый `args_hash` три и более раз.
**Лечение.** Отпечаток вызова, лимит 3, стоп-код `repeated_action`. И обязательно — правка `hint`: повтор почти всегда его вина.
**Тест.** Сценарий фиктивной модели, повторяющей вызов, завершается за 3 фактических выполнения, не больше.

## AP-04. Молчаливая обрезка

**Симптом.** Агент делает уверенные выводы по неполным данным.
**Механизм.** Вывод обрезан по лимиту, но агент об этом не знает.
**Признак в трейсе.** `truncated: true` на шаге, предшествующем неверному решению.
**Лечение.** Голова и хвост вместо только головы; текстовая пометка внутри результата; подсказка «запроси диапазон».
**Тест.** Результат длиннее лимита обязан содержать маркер обрезки в тексте, а не только в атрибуте.

## AP-05. Автоповтор неидемпотентного

**Симптом.** Письмо ушло дважды; дубликаты в базе.
**Механизм.** Сетевой таймаут, обёртка сделала автоматический повтор, операция не идемпотентна.
**Признак в трейсе.** Два спана `tool.send_*` с одинаковым `args_hash` и `retry_n > 0`.
**Лечение.** Классификация операций A–E; ключ идемпотентности из содержимого; повторы только для `retryable` и только для трёх кодов.
**Тест.** Двойной вызов с одинаковыми аргументами даёт одно фактическое действие и ответ «уже выполнено».

## AP-06. Описание для разработчика, а не для модели

**Симптом.** Агент вызывает не тот инструмент или не вызывает нужный.
**Механизм.** `description` написан как комментарий для коллеги: «утилита для работы с данными».
**Признак в трейсе.** Вызов соседнего инструмента при наличии подходящего; `validation`-ошибки на очевидных полях.
**Лечение.** Десять правил из [раздела 2.3](../02-tool-calling/#23-описание-инструмента--это-интерфейс-и-его-читает-модель), особенно «когда НЕ использовать» и пример вызова.
**Тест.** Тест описаний: 5 положительных и 5 отрицательных формулировок задач на инструмент, не более одной ошибки.

## AP-07. Слишком много инструментов

**Симптом.** Схемы занимают четверть окна; точность выбора падает.
**Механизм.** Подключили всё «на всякий случай», включая три MCP-сервера.
**Признак в трейсе.** `ctx.tools_tokens` больше 15% окна; используется меньше трети инструментов.
**Лечение.** Динамический набор по фазе задачи; `allow`-список; отключение серверов, используемых реже чем в 10% прогонов.
**Тест.** Проверка в CI: число инструментов в наборе не выше порога; доля `tools_tokens` не выше 10%.

## AP-08. Инструмент со скрытым состоянием

**Симптом.** Одинаковый вызов даёт разные результаты; трейс выглядит корректным, поведение — нет.
**Механизм.** `search` иногда ищет по коду, иногда по документации, в зависимости от внутреннего флага.
**Признак в трейсе.** Одинаковые `args_hash` с разными `bytes_out` и разным смыслом результата.
**Лечение.** Два инструмента с честными именами; никакого неявного состояния между вызовами.
**Тест.** Два одинаковых вызова подряд дают идентичный результат (для чистых чтений).

## AP-09. Цель живёт только в первом сообщении

**Симптом.** К десятому шагу агент увлечённо делает не ту задачу.
**Механизм.** Цель утонула в середине контекста; никакого якоря нет.
**Признак в трейсе.** `thought` на поздних шагах не упоминает исходную цель; действия не относятся к текущему пункту.
**Лечение.** План-файл с иммутабельной целью; выжимка плана в начале окна; якорь с целью и критерием в конце окна.
**Тест.** Валидатор: строка «Цель» в плане совпадает с задачей по хешу; отсутствие `edit_goal` среди инструментов.

## AP-10. Пункты плана без критериев

**Симптом.** Агент ставит `done` на пункт «изучить архитектуру».
**Механизм.** Критерий сформулирован так, что его нельзя не выполнить.
**Признак в трейсе.** `plan.updated` с `to: done` и пустой заметкой.
**Лечение.** Каждый пункт содержит команду, число или имя файла в критерии; валидатор плана отклоняет остальные.
**Тест.** Валидатор плана падает на пункте без проверяемого критерия и на `done` с пустой заметкой.

## AP-11. Бесконечная подготовка

**Симптом.** Двенадцать шагов чтения и ни одного изменения.
**Механизм.** Исследовать безопаснее, чем действовать, а ограничения на фазу нет.
**Признак в трейсе.** Шесть и более подряд вызовов инструментов класса A.
**Лечение.** Лимит подряд идущих шагов только чтения (5); мягкое вмешательство с требованием изменения или обновления плана.
**Тест.** Сценарий, где модель только читает, завершается вмешательством не позже 6-го шага.

## AP-12. Перепланирование без лимита

**Симптом.** Шесть версий плана за прогон, задача не решена.
**Механизм.** `replan` доступен без ограничений и без обязательной причины.
**Признак в трейсе.** `replan_n` больше 3; причины короткие и общие.
**Лечение.** `MAX_REPLANS = 3`; причина минимум 40 символов с указанием неверной предпосылки; остаток лимита сообщается модели.
**Тест.** Четвёртый `replan` возвращает `replan_limit`; `replan` с короткой причиной отклоняется.

## AP-13. Критик видит рассуждения автора

**Симптом.** Критик принимает 97% результатов при pass rate 62%.
**Механизм.** Критик получает всю историю и подхватывает логику автора.
**Признак в трейсе.** Спан критика содержит `thought` автора; `verdict: accept` почти всегда.
**Лечение.** Чистый контекст: только задача, критерий, результат. Промпт «найди причины отклонить». Машинный критик первым.
**Тест.** Калибровка: на 30 размеченных случаях каппа выше 0,6 и `false_accept` ниже 10%.

## AP-14. Расширение скоупа «заодно»

**Симптом.** Агент чинит один баг и попутно рефакторит три модуля.
**Механизм.** Нет клапана для импульса «заодно», и всё попадает в текущий прогон.
**Признак в трейсе.** Изменения в файлах, не упомянутых ни в одном пункте плана.
**Лечение.** `BACKLOG.md` и инструмент `add_backlog`; `reject`-условие в golden set на изменения вне ожидаемых путей.
**Тест.** Задача с соблазном («в коде рядом есть очевидное дублирование») проходит только если диф ограничен ожидаемыми файлами.

## AP-15. Компакция без проверки потерь

**Симптом.** Агент «забыл» решение, принятое 15 шагов назад, и выбирает заново, возможно иначе.
**Механизм.** Сжатие выбросило причины решений как «неважное».
**Признак в трейсе.** `memory.compacted` с `decisions_lost > 0` либо повторный выбор после компакции.
**Лечение.** `record_decision`; закрытый список обязательных разделов конспекта; валидатор, дополняющий потерянное механически.
**Тест.** После компакции все зарегистрированные решения присутствуют в конспекте; `decisions_lost` равно нулю.

## AP-16. Критичное в середине окна

**Симптом.** Агент нарушает правило, которое точно присутствует в контексте.
**Механизм.** Правило оказалось в середине большого окна, где внимание слабее.
**Признак в трейсе.** Правило есть в `window`, нарушение произошло; окно больше 40 000 токенов.
**Лечение.** Раскладка из [раздела 4.9](../04-memory/#49-позиционные-эффекты-где-в-окне-что-размещать); критичное в первых 300 токенах и в якоре в конце. Лучше — сделать правило исполняемым в политике.
**Тест.** A/B на 20 задачах: доля нарушений при правиле в середине против правила в начале и якоре.

## AP-17. Порог компакции 90%

**Симптом.** Ошибка провайдера о длине запроса ровно в момент компакции.
**Механизм.** Для сжатия нужно место, а его уже нет.
**Признак в трейсе.** `fatal` с ошибкой длины; `ctx.total_tokens` выше 90% окна.
**Лечение.** Порог 70%; вход не выше 70% окна; ошибка длины приводит к принудительной компакции и одному повтору, а не к `fatal`.
**Тест.** Прогон с намеренно большими выводами достигает компакции и завершается штатно.

## AP-18. Факты без источника и TTL

**Симптом.** Агент уверенно опирается на факт, который был верен полгода назад.
**Механизм.** Автозапись фактов без `source`, `confidence`, `ttl_days` и `verify`; ревизии нет.
**Признак в трейсе.** Действие по факту, чей `added` старше полугода и `verify` отсутствует.
**Лечение.** Формат факта из [раздела 4.7](../04-memory/#47-семантическая-память-факты-ttl-конфликты); `confidence: medium` для автозаписи; ревизия раз в спринт.
**Тест.** Валидатор: факт без `source` или без `ttl_days` не сохраняется; просроченные помечаются.

## AP-19. Нет передачи смены

**Симптом.** Новая сессия начинает с нуля и повторяет двадцать шагов исследования.
**Механизм.** Состояние жило только в контексте, который кончился.
**Признак в трейсе.** Два прогона одной задачи с почти идентичными первыми шагами.
**Лечение.** `handoff.md` в конце каждой сессии и при аварийном завершении; `resume()` со сверкой записанного с фактическим.
**Тест.** Прерванный прогон продолжается второй сессией без повторного исследования; `resume()` обнаруживает подставное расхождение.

## AP-20. Только векторный поиск

**Симптом.** RAG не находит по коду ошибки, по имени параметра, по номеру версии.
**Механизм.** Векторный поиск слаб на редких токенах и числах.
**Признак в трейсе.** Низкий recall на категории `exact_match` при нормальном на `factual`.
**Лечение.** Гибридный поиск: вектор плюс BM25, слияние через RRF; исходный запрос всегда в наборе.
**Тест.** Набор оценки содержит 20% `exact_match`; recall@30 на них выше 0,90.

## AP-21. Нет порога отсечения

**Симптом.** Система всегда что-то отвечает, даже когда в корпусе ответа нет.
**Механизм.** Топ-k возвращается всегда, независимо от релевантности.
**Признак в трейсе.** Низкие скоры реранка, ответ дан; отсутствие ответов «не нашёл» вообще.
**Лечение.** Порог, настроенный на наборе `no_answer`; обязательное цитирование; `check_citations`.
**Тест.** На 20 вопросах, ответов на которые нет, честное молчание минимум в 18.

## AP-22. Чанк без контекста

**Симптом.** Фрагменты в индексе непонятны в одиночку: «Значение по умолчанию — 30 секунд».
**Механизм.** В текст эмбеддинга не включены заголовок документа и путь в структуре.
**Признак.** Прочитайте 20 случайных чанков: если половина непонятна — диагноз подтверждён.
**Лечение.** `for_embedding()` с `doc_title` и `heading_path`; иерархический чанкинг с родительскими блоками.
**Тест.** Проверка в CI: доля чанков короче N символов и без `heading_path` равна нулю.

## AP-23. Роли как у людей

**Симптом.** Шесть агентов, стоимость в шесть раз выше, качество ниже одиночного.
**Механизм.** Структура команды скопирована с людей; границы не соответствуют границам задачи.
**Признак в трейсе.** Много передач, мало решений у супервизора; повторное вхождение в контекст.
**Лечение.** Начать с одиночного агента; мульти-агент только при измеренном выигрыше или снятом ограничении; протокол сравнения 7.9.
**Тест.** Отчёт сравнения с честной базовой линией: pass rate, `cost_per_success`, p95, доля конфликтов.

## AP-24. Нет поиска конфликтов

**Симптом.** Два подагента исправили одно место по-разному; изменения взаимно уничтожаются.
**Механизм.** Результаты слиты без проверки пересечений.
**Признак в трейсе.** Один путь в `evidence` двух подагентов; оба `status: done`.
**Лечение.** `find_conflicts` перед слиянием; конфликт эскалируется, а не решается молча; `forbidden` в `SubTask` для областей другого подагента.
**Тест.** Сценарий с двумя подзадачами на один файл: слияние возвращает конфликт, а не результат.

## AP-25. Безопасность как текст

**Симптом.** Все запреты — просьбы в промпте; при первом нестандартном входе они не работают.
**Механизм.** Один барьер вместо шести, и он зависит от поведения модели.
**Признак.** В `docker run` нет ограничивающих флагов; политика прав отсутствует или разрешает по умолчанию.
**Лечение.** Барьеры 2–5 из [раздела 11.5](../11-security/#115-шесть-независимых-барьеров): `allow`-список, правило потока, подтверждения, песочница.
**Тест.** Табличные тесты политики; негативные тесты изоляции; набор инъекций в CI.

## AP-26. Недоверенное без разметки

**Симптом.** Агент выполнил инструкцию, встреченную в веб-странице или тикете.
**Механизм.** Вывод инструментов попадает в контекст как обычное сообщение.
**Признак в трейсе.** Действие, чьи аргументы производны от недоверенных данных; `taint` не отслеживается.
**Лечение.** Обёртка с метками и нормализацией; правило в первых строках промпта; правило потока данных; `CONFIRM` на классах D и E.
**Тест.** `injection-suite.yaml` на 20+ сценариев плюс 5+ контрольных задач; обе метрики (отражения и ложные отказы).

## AP-27. Секреты в окружении агента

**Симптом.** В трейсе или в выводе `env` видны токены.
**Механизм.** Секреты переданы процессу агента «чтобы инструменты работали».
**Признак в трейсе.** Срабатывание `secret.redacted`; `bytes_out` у `env`-подобных команд.
**Лечение.** Секретов нет у процесса агента: инструменты выполняются на хосте и подставляют их сами; сканер на выходе; срабатывание — инцидент.
**Тест.** Прогон команды `env` внутри песочницы не содержит ни одного секрета; сканер срабатывает на подставном значении.

## AP-28. Средние вместо процентилей

**Симптом.** «Средняя латентность 4 секунды» при жалобах на тридцать.
**Механизм.** Распределения тяжелохвостые; среднее скрывает хвост.
**Признак.** На дашборде нет p95 и p99.
**Лечение.** p50/p95/p99 для латентности и стоимости; гистограмма числа шагов.
**Тест.** Проверка дашборда: пять обязательных графиков из [раздела 10.7](../10-observability/#107-метрики-пять-графиков-которые-нужны-всегда) присутствуют.

## AP-29. Один прогон как доказательство

**Симптом.** «Поправил промпт, стало лучше» — проверено на одной задаче.
**Механизм.** Недетерминированная система, выборка размера один.
**Признак.** В описании изменения нет чисел с интервалами.
**Лечение.** Golden set, минимум 5 прогонов на задачу, интервалы Уилсона, парное сравнение по задачам.
**Тест.** CI не пропускает пулл-реквест с правкой промпта без приложенного отчёта эвалов.

## AP-30. Промпт не в git

**Симптом.** Промпт правится в проде через админку; откатить нельзя.
**Механизм.** Промпт воспринимается как настройка, а не как код.
**Признак.** Невозможно сделать `git diff` по промпту; нет истории изменений.
**Лечение.** Файлы в `prompts/vN/`, `current` как символическая ссылка, `CHANGELOG.md` с эффектами, ревью, эвалы как ворота.
**Тест.** Проверка в CI: `prompts_version` из трейса совпадает с версией в репозитории; отсутствие промптов вне `prompts/`.

## Как добавлять свои

Самый ценный антипаттерн — ваш собственный, потому что он про вашу систему. Формат тот же: симптом, механизм, признак в трейсе, лечение, тест.

**Правило.** Запись добавляется только после того, как лечение применено и тест написан. Иначе каталог превращается в список жалоб.

**Ритуал.** Раз в две недели: посмотреть распределение отказов по слоям, взять самый частый, разобрать три примера, починить слой, добавить запись и тест. Двенадцать записей за квартал — это двенадцать классов проблем, которые больше не вернутся незамеченными.
