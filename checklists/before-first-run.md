# Чек-лист: перед первым запуском на реальных данных

[← Все чек-листы](README.md) · Время: 20 минут

Момент применения: агент работает на фикстурах, вы собираетесь дать ему настоящий репозиторий, настоящую базу или настоящие документы. Это самый недооценённый рубеж: именно здесь случаются первые «а он взял и удалил».

---

## 1. Границы (обязательно, без исключений)

- [ ] Записаны ответы на пять вопросов о радиусе поражения ([раздел 8.2](../08-sandboxes/#82-радиус-поражения-как-считать)): что может прочитать, что изменить, куда отправить, сколько съесть, что при полном захвате
- [ ] Ни на один из пяти вопросов ответ не «не знаю» и не «в принципе всё»
- [ ] Агент работает в контейнере с `--read-only` и явным списком изменяемых путей
- [ ] Внутри контейнера непривилегированный пользователь, не root
- [ ] Смонтирован отдельный `git worktree` или копия данных, а не основной рабочий каталог
- [ ] `~/.ssh`, `~/.aws`, `~/.config`, `/var/run/docker.sock` не смонтированы
- [ ] Сеть: `--network none` либо белый список хостов; отклонения логируются
- [ ] Заданы лимиты CPU, памяти (с `--memory-swap`), `pids`, файловых дескрипторов
- [ ] Негативные тесты изоляции прогнаны и все корректно провалились внутри песочницы

## 2. Обратимость

- [ ] Каждое изменение отменяется одной командой (git, транзакция, снапшот)
- [ ] Проверено на практике: сделайте изменение агентом и откатите, замерьте время
- [ ] Все действия классов D и E ([раздел 2.10](../02-tool-calling/#210-опасные-инструменты-dry-run-подтверждение-откат)) требуют подтверждения
- [ ] Подтверждение содержит описание эффекта: что, сколько, обратимо ли, как откатить
- [ ] Есть `DANGEROUS.md` со списком инструментов классов C–E и способом откита каждого

## 3. Бюджеты

- [ ] Заданы все четыре: шаги, время, токены, деньги
- [ ] Проверка бюджета стоит **до** вызова модели
- [ ] Есть мягкий порог 80% с указанием подвести итог
- [ ] Известна ожидаемая стоимость одного прогона; лимит установлен в 3–5 раз выше
- [ ] Есть внешний потолок на сутки, при исчерпании — остановка неинтерактивных прогонов

## 4. Секреты и данные

- [ ] В окружении процесса агента нет ни одного секрета
- [ ] Инструменты, которым нужны секреты, выполняются вне песочницы и подставляют их сами
- [ ] Работает сканер утечек на выходе из песочницы
- [ ] Сканер проверен на подставном значении (внесите фиктивный ключ, убедитесь, что срабатывает)
- [ ] Если в данных есть персональные — применён белый список полей по цели
- [ ] Понятно и записано, что именно уходит провайдеру модели в контексте

## 5. Наблюдаемость

- [ ] Трейс пишется всегда, не под флагом отладки
- [ ] У каждой записи есть `run_id`
- [ ] Пишутся `in_tokens`, `out_tokens`, `cost_usd`, `latency_ms`, `model` по шагам
- [ ] Пишутся `tool`, `args_hash`, `status`, `error_code`, `bytes_out`, `truncated`
- [ ] Работает команда, печатающая прогон в читаемом виде (`make trace RUN=...`)
- [ ] Проверено: по `run_id` вы находите первое расхождение меньше чем за минуту

## 6. Стоп-условия

- [ ] Каждый выход из цикла имеет код причины из [таблицы 1.7](../01-agent-basics/#17-стоп-условия-девять-причин-закончить-прогон)
- [ ] Есть счётчик пустых шагов с лимитом
- [ ] Есть детектор повторяющихся вызовов по отпечатку
- [ ] Ошибка инструмента не роняет прогон, а попадает в историю как данные
- [ ] Прогон, прерванный сигналом `SIGTERM`, завершается через безопасное завершение

## 7. Первый прогон: как именно запускать

- [ ] На копии данных, не на оригинале — даже при всех барьерах
- [ ] С `max_steps` вдвое ниже планового: посмотреть поведение, а не результат
- [ ] С человеком у терминала, а не в фоне
- [ ] С заранее решённым критерием «останавливаю руками, если увижу X»
- [ ] После прогона трейс прочитан целиком, а не только финальный ответ

## 8. Что смотреть в первом трейсе

- [ ] Все ли вызовы инструментов осмысленны — нет ли вызова «наугад»
- [ ] Есть ли `truncated: true` — если да, агент делал выводы по неполным данным
- [ ] Есть ли повторяющиеся `args_hash` — если да, `hint` не работает
- [ ] Растёт ли `in_tokens` линейно — если да, компакция не настроена или не нужна
- [ ] Какой `stop_reason` — и соответствует ли он вашему ожиданию
- [ ] Сколько стоило — и совпадает ли с оценкой

---

## Красные флаги: не запускайте, если

**Не знаете, что произойдёт при худшем сценарии.** Это не осторожность, это отсутствие информации, необходимой для решения.

**Откат не проверен на практике.** «Там же git» — это гипотеза, пока вы не откатили реальное изменение агента и не замерили время.

**Секреты доступны процессу агента.** Никакие запреты в промпте это не компенсируют: одна отладочная команда, и они в контексте.

**Трейс включается вручную.** Первый же интересный прогон вы упустите.

**Нет ни одного стоп-условия кроме числа шагов.** Прогон найдёт способ потратить бюджет.
