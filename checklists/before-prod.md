# Чек-лист: перед выкатом на пользователей

[← Все чек-листы](README.md) · Время: 60 минут · Теория: [Модуль 13](../13-production/)

Применяется в дополнение к [before-first-run.md](before-first-run.md), а не вместо него. Все пункты первого чек-листа должны быть закрыты.

---

## 1. Измеримость (без этого раздела дальше идти нельзя)

- [ ] Есть golden set из 40+ задач с `accept` и непустым `reject`
- [ ] 5+ категорий, распределение по сложности с 30% сложных
- [ ] 10–15% задач категории `safety`: правильный ответ — отказ или запрос подтверждения
- [ ] Есть слепой поднабор (20–25%), формулировки которого не видели правившие промпты
- [ ] Каждая задача прогоняется минимум 5 раз; интервалы по Уилсону
- [ ] Базовая линия лежит в файле с версиями модели, промптов и политики
- [ ] `make eval` возвращает ненулевой код при регрессии по правилам [9.8](../09-evals/#98-регрессии-базовая-линия-и-ci)
- [ ] Известен `cost_per_success` и он ограничен сверху
- [ ] Известна доля `done_unverified` — какую часть успехов вы принимаете на слово

## 2. Версионирование и откат

- [ ] Промпты в git, в каталоге с версией; `current` — символическая ссылка
- [ ] Версия промпта внутри файла и в каждом трейсе
- [ ] Есть `CHANGELOG.md` промптов: изменение, причина, измеренный эффект
- [ ] Собран манифест релиза со всеми полями из [13.2](../13-production/#132-что-именно-вы-выкатываете-инвентарь-версий)
- [ ] Версии моделей заданы снапшотами, не алиасами; это проверяется автоматически
- [ ] Откат — одна команда, замерено секундомером, меньше минуты
- [ ] В этом релизе только добавление полей данных; ничего не удалено и не переименовано
- [ ] Старая версия не падает на данных новой (проверено)

## 3. Ворота выката

- [ ] Ворота 1: линтер, типы, юнит-тесты, табличные тесты политики — зелёные
- [ ] Ворота 2: дымовой набор — без регрессии
- [ ] Ворота 3: полный golden set — без регрессии по всем правилам
- [ ] Ворота 4: набор инъекций пройден полностью, ложных отказов на контролях нет
- [ ] Ворота 5: `cost_per_success` не вырос более чем на 30%
- [ ] Ни одно из ворот не проходило в режиме «предупреждение»

## 4. Безопасность

- [ ] Есть `SECURITY.md`: активы, источники недоверенного входа, барьеры, последствия пробития
- [ ] Работают барьеры 2–5 из [11.5](../11-security/#115-шесть-независимых-барьеров), а не только текст в промпте
- [ ] Политика прав: последнее правило — `DENY` для всего; запреты выше разрешений
- [ ] Табличные тесты политики покрывают порядок правил
- [ ] Правило потока данных: недоверенное не управляет опасными действиями
- [ ] Получатели внешних действий — из белого списка, не из данных
- [ ] Аудит: решения политики, подтверждения, срабатывания сканера — пишутся, только на добавление
- [ ] Проведено ревью списка прав: за последний месяц права только сужались или расширялись осознанно с записью

## 5. Наблюдаемость и алерты

- [ ] Пять обязательных графиков из [10.7](../10-observability/#107-метрики-пять-графиков-которые-нужны-всегда) собраны и читаются
- [ ] Латентность и стоимость показаны процентилями, не средними
- [ ] Список алертов соответствует [10.8](../10-observability/#108-алерты-на-что-будить-человека); в каждом есть ссылки на примеры
- [ ] Ни один алерт не срабатывает чаще одного раза в день на нормальной нагрузке
- [ ] Работает хвостовое семплирование: 100% провалов, 5% успехов
- [ ] Редактирование секретов применяется до записи

## 6. SLO и деградация

- [ ] Определены SLO с числами: успешность, верифицированность, латентность p95, стоимость, безопасность, доступность
- [ ] SLO согласованы с теми, кто будет предъявлять претензии
- [ ] Есть бюджет ошибок и правило его использования
- [ ] Реализованы уровни деградации; уровень пишется в трейс и сообщается пользователю
- [ ] Есть автомат отключения на ошибки провайдера
- [ ] Есть суточный и месячный потолок расходов с алертом

## 7. Выкат

- [ ] Канарейка: 5% трафика, минимум 200 прогонов и 2 часа
- [ ] Разделение стабильное по пользователю или тенанту
- [ ] Критичные тенанты в списке исключений
- [ ] Правила автоматического отката реализованы и проверены на подставном ухудшении
- [ ] Определены шаги наращивания: 5 → 25 → 50 → 100 с паузами и проверками
- [ ] Назначен ответственный на время выката, он доступен

## 8. Эксплуатация

- [ ] У дежурного есть инструкция на одну страницу: метрики, трейсы, откат, кого звать
- [ ] Доступы дежурного проверены на практике, а не в теории
- [ ] У дежурного есть право откатить без согласований
- [ ] Проведены учения по откату в спокойное время
- [ ] Есть `incident-response.md` и он прочитан теми, кто дежурит
- [ ] Есть еженедельный прогон эвалов по расписанию для обнаружения внешнего дрейфа

## 9. Пользовательский опыт

- [ ] Пользователь видит, что агент работает (прогресс шагов), а не пустое ожидание
- [ ] Неуспешный прогон возвращает полезный отчёт, а не «не удалось»
- [ ] Ответы содержат ссылки на источники там, где это применимо
- [ ] Есть способ сообщить о плохом ответе, и он привязан к `run_id`
- [ ] Пользователь предупреждён, если работает деградированный режим

---

## Красные флаги: не выкатывайте, если

**Нет golden set.** Вы не сможете отличить улучшение от ухудшения и не заметите деградацию.

**Откат не проверен секундомером.** Во время инцидента непроверенная процедура растянется втрое.

**Ворота безопасности проходили в режиме предупреждения.** Это не ворота.

**Алерты уже игнорируются на стадии тестирования.** В проде их замьютят на второй день.

**Никто не назначен ответственным на время выката.** Канарейка без наблюдателя — это просто выкат на 5%.

---

## Подпись

Релиз считается одобренным, когда все пункты закрыты либо явно приняты как риск. Запишите в манифест: `approved_by` и `approved_at`, а также список принятых рисков. Это не бюрократия: через месяц при разборе инцидента вы захотите знать, что именно было известно на момент выката.
